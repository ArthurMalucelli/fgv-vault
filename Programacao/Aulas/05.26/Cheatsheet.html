Modelo mental (lê antes de tudo)

DataFrame é a tabela inteira (2D, várias colunas e linhas). Series é uma coluna sozinha (1D). Quando tu pega df["c"], recebe Series. Quando pega df[["c1","c2"]] (lista), recebe DataFrame. Series tem métodos de coluna (mean, str.upper, value_counts); DataFrame tem operações sobre múltiplas colunas.

Filtro de linha sempre tem 2 etapas mentais, mesmo numa linha só. Primeiro, cria uma Series booleana com a condição (df["c"] == "X" retorna True/False por linha). Segundo, aplica essa Series dentro do df[...]. O pandas vê uma Series booleana ali dentro e entende: "fica só com as linhas True". Não dá pra "filtrar com string", só com booleana.

Atualizar coluna vs destruir DataFrame. df["c"] = ALGO atualiza a coluna c, mantém o resto do DataFrame intacto (esquerda é coluna). df = ALGO sobrescreve o DataFrame inteiro (esquerda é variável). Se tu fizer df = df["c"].str.lower(), o df vira uma Series e as outras colunas somem.

Por que existe .str. Métodos de string Python (upper, replace, contains) funcionam em uma string só. Coluna do pandas é Series com centenas de strings. .str é a ponte: aplica o método em cada string da coluna, retorna Series nova. Sem .str, dá erro porque Series não tem upper, replace, etc.

groupby = split, apply, combine. df.groupby("c")["v"].mean() divide o df em pedaços por valor de c, calcula a média de v em cada pedaço, junta tudo numa Series com c no índice. Equivalente direto da tabela dinâmica do Excel.

merge = PROCV de tabela inteira. Junta dois DataFrames por uma chave em comum (coluna que existe nos dois). how="inner" só mantém chaves presentes nos dois lados (descarta o que sobra), mas ADICIONA todas as colunas do segundo DataFrame que enriquecem as linhas. Se a chave real precisa de várias colunas, passa lista (on=["k1","k2","k3"]), senão vira produto cartesiano e explode.

Método tem (), atributo não. df.shape, df.columns, df.dtypes são atributos (sem parêntese). df.head(), df.mean(), df["c"].str.upper() são métodos (com parêntese). Esquecer () não dá erro, retorna o objeto-método em vez do valor (saída do tipo <bound method>).

Como ler um traceback. Erro vermelho gigante: ignora as 20 linhas do meio. A última linha diz o que houve (KeyError, TypeError, etc) e qual valor causou. A primeira linha do traceback diz qual célula tua causou. Dois pedaços, ignora o resto.

17. Caso real: postos + distrib (margem)

# 1. Cria Mes em postos (formato YYYY-MM):
postos["Mes"] = (postos["Data da Coleta"].str[6:10] + "-"
                 + postos["Data da Coleta"].str[3:5])

# 2. Junta pela chave TRIPLA (sem isso, cartesiano):
juntos = pd.merge(postos, distrib,
    on=["Municipio","Produto","Mes"], how="inner")

# 3. Margem (revenda − atacado):
juntos["margem"] = juntos["Valor de Venda"] - juntos["Preco_Distribuicao"]

# 4. Margem média por bandeira (ranking):
juntos.groupby("Bandeira")["margem"].mean().sort_values(ascending=False)

20. Regras-mãe (decora estas)

  • = atribui, == compara. Errar é clássico.
  • Estatística sempre em coluna: df["c"].mean(), não df.mean().
  • Atualizar coluna: esquerda é df["c"], nunca só df.
  • Booleano: & | ~, cada cond entre parênteses.
  • loc fim inclusivo, iloc fim exclusivo.
  • Métodos com (); atributos sem (shape, columns, dtypes).
  • sort_values não persiste sozinho. Reatribui.
  • Sempre .str antes de função de string.
  • copy() ao criar subset que vai ser modificado.
  • Chave de merge incompleta → cartesiano. Confere shape depois.
  • Kernel restart zera tudo. Roda tudo em ordem (Restart and Run All).
